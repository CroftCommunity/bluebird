# RUN-02 — The garden (read path) (Phase 1)

`Date: 2026-07-14. Branch: claude/skylite-v1-build-plan-heoxq4. Phase: 1 of the
v1 build plan. Status: executed — see RUN-02-SUMMARY.md.`

## Goal

Build the read path: an `app.bsky.feed.getAuthorFeed` client over the public
AppView, merge N author feeds newest-first, and render a big, bright, no-counts
garden from a checked-in dev inclusion list.

## Scope (from build plan Phase 1)

- `getAuthorFeed` client over `public.api.bsky.app`, cursor-aware pagination,
  polite backoff.
- Merge N author feeds newest-first (the plan's headline testable unit).
- Post rendering: text (facets), images with alt, video posters, external link
  cards; label-bearing posts filtered per **D3**; links gated per **D7**.
- Inclusion list from a checked-in dev fixture.
- Big bright Lite UI: high-contrast, large text, **no counts anywhere**.
- Tests: merge logic unit-tested against fixtures; hermetic e2e renders a garden
  from mocked responses; one `@live` smoke, local only.

## Decisions applied

- **D3 (honor ATProto labels)** — taken at the plan default. Known adult/graphic
  labels (and `!hide`/`!takedown`/`!warn`) HIDE a post; negated labels ignored;
  author labels count. No blur-with-reveal — a reveal control is a decoy door in
  a walled garden. Sky-Shield AI moderation remains out of v1.
- **D7 (gate external links)** — taken at the plan default. Every in-text link
  and external card opens a "this link leaves Skylite" interstitial naming the
  domain; cards render domain + title + description only, no outbound image.

  *These two `[confirm]` items were taken at their plan defaults because the
  AskUserQuestion checkpoint aborted (a tool stream error) and the user said
  "continue"/"keep going". Both are low-risk defaults spelled out in the plan.
  Flagged here for veto.*

- **Inclusion ceiling made real:** reposts are dropped in merge. An included
  author reposting an excluded author would otherwise smuggle that author past
  the ceiling ("she only ever sees who you've included"). Confirmed against the
  live AppView, where `actor=bsky.app`'s feed leads with a repost of an outside
  account — precisely the case being closed.

## House rules honored

- Hermetic tier only in CI; `@live` in a separate config (`e2e:live`), never in
  `npm test` / push CI; no credentials in-repo.
- No new runtime dependencies (still zero — vanilla TS). Only dev tooling.
- CSP unchanged: reads to `public.api.bsky.app`, blob images from `cdn.bsky.app`.
  No inline script/style; all post content rendered via `textContent`.

## Verify-in-phase

- **Rate-limit / politeness:** exponential backoff honoring `Retry-After` on
  429/5xx (unit-tested); `posts_no_replies` filter and bounded pagination keep
  requests small. SW-level caching is Phase 3, as the plan sequences it.
- **Reachability:** the unauthenticated `getAuthorFeed` grounding fact re-checked
  live from the shell (200 + JSON).
